## Real Chat Engine Architecture

The chat engine is wired via `dsh-base` bundle (`packages/bundle/base/cordis.patch.yml`):

- `dsh-llm` — LLM service registry
- `dsh-llm-deepseek` — DeepSeek provider (OpenAI-compatible /chat/completions)
- `dsh-session` — conversation/session persistence
- `dsh-agent` — agent registration/dispatch
- `dsh-agent-loop` — the chat loop: user msg to LLM to tool calls to response
- `dsh-agent-default-model` — default: provider=deepseek-official, model=deepseek-v4-flash
- `dsh-system-prompt` — system prompt assembly
- `dsh-tools` — tool registry (bash, fs, editor, web, etc.)
- `dsh-credentials-local` — resolves DEEPSEEK_API_KEY from env/.env
- `interaction/` sub-packages — user-questions, tool-ask-user, user-approval, commands

## LLM Adapter Configuration

`dsh-llm-deepseek` uses `POST {baseURL}/chat/completions` with `Authorization: Bearer {apiKey}`. Env vars:

- `DEEPSEEK_API_KEY` — the API key (CredentialRef, resolved from env/.env)
- `DEEPSEEK_BASE_URL` — endpoint base (defaults to `https://api.deepseek.com`)

**OpenRouter compatibility (Rule 1):** OpenRouter exposes the same `/chat/completions` endpoint. To test with OpenRouter:

- `DEEPSEEK_BASE_URL=https://openrouter.ai/api/v1`
- `DEEPSEEK_API_KEY` = value from .env OPENROUTER_API_KEY
- model: `qwen/qwen3.7-flash` (from .env OPENROUTER_MODEL)
