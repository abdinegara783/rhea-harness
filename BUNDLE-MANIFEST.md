## Real Persistence Architecture

```
dsh-base bundle (wires persistence)
 ├─ dsh-session-persistence       (persistence service interface)
 ├─ dsh-session-persistence-jsonl (JSONL file-based storage backend)
 ├─ dsh-session-persistence-sqlite (SQLite storage backend)
 ├─ dsh-session-projection        (session title/stats projection for sidebar)
 ├─ dsh-session-projection-cache  (cached projections for fast sidebar render)
 ├─ dsh-session-stats            (turn/token stats per session)
 ├─ dsh-session-title            (auto-generate chat titles for sidebar)
 ├─ dsh-storage                  (storage service interface)
 ├─ dsh-storage-domain           (storage domain types)
 ├─ dsh-storage-json             (JSON file storage backend)
 └─ dsh-storage-sqlite           (SQLite storage backend)
```

Client UI (sidebar with session list) is `dsh-client-ui-sidebar`, a dependency
of `dsh-web-app`. Session management is handled by `dsh-client-runtime` +
`dsh-client-connection` which call the session RPC methods.

## RPC methods for session management (already in apiproxy from Phase 2.1)

- session.list — list all conversations (sidebar)
- session.create — create new chat
- session.history — retrieve message history (reopen chat)
- session.search — search past conversations
- session.rename — rename a conversation
- session.fork — fork a conversation
- session.cancel — stop AI generation (partial answer saved)

## Acceptance Criteria (from journey summary)

1. Chat baru, kirim pesan, tutup app, buka lagi, chat masih ada
2. Klik chat di sidebar, isi muncul
3. Buka beberapa chat bergantian, tidak tertukar
4. Hapus chat, hilang dari daftar
5. Tambah pesan di chat lama, tersimpan

## Verification Strategy

1. Boot dsh web with OpenRouter env (Rule 1)
2. Create a session via RPC (session.create)
3. Send a prompt via RPC (session.prompt) with LLM call
4. List sessions via RPC (session.list) — verify session appears
5. Read history via RPC (session.history) — verify messages persisted
6. Restart the server, list sessions again — verify session survives restart (AC 1)
7. Static: verify SQLite/JSONL storage adapters present in lib/
8. Static: verify sidebar UI component in web bundle (session list rendering)

## Compliance

- SQLite: public domain (not a license, but royalty-free) — compliant
- Data is local (no cloud storage) — privacy: data stays on user machine
- No new API keys or external services
